# 模型参数必须由用户明确决定

## 背景

参数注册表为温度、采样概率、最大回复长度、思考强度等参数定义了默认值。端点编辑窗口和会话参数窗口会把这些默认值直接填入控件。用户即使没有调整参数，只要保存窗口，软件也会把所有控件中的值保存下来并发送给模型。

这会产生两个问题：

1. 软件替用户选择了本应由用户或模型决定的参数。
2. 不支持其中某些参数的模型会拒绝整个请求。OpenAI 新格式（`/v1/responses`）尤其容易遇到这个问题，但根因存在于所有接口格式共用的参数编辑方式中。

## 目标

- 用户没有明确设置的参数不保存、不发送。
- 用户可以选择继承上级设置、自己设置，或者明确让模型决定。
- “由模型决定”必须阻止上级已经设置的值继续进入请求。
- 已经保存的旧参数继续生效，不猜测它们当初由谁设置，也不迁移或删除。
- 所有接口格式遵守同一规则，不为 OpenAI 新格式增加孤立特例。

## 不在本次范围

- 不根据模型名猜测它支持哪些参数。第三方兼容端点可以使用任意模型名，无法可靠推断能力。
- 不自动删除旧配置中已经保存的参数。
- 不修改用户自行添加的自定义参数；用户输入自定义参数本身就是明确设置。
- 不修复“测试连接的最小回复长度被正常聊天参数覆盖”的通用 bug，该问题已单独记在 `docs/other/todo.txt`。
- 不顺带修复已有会话在缺少会话参数时仍可能读取工作区参数的文档与代码不一致问题。

## 参数的三种存储状态

继续使用现有参数对象，不增加第二份状态名单，也不改变参数值的数据结构。

| 当前层保存的内容 | 含义 | 是否继续读取上层 | 是否发送 |
|---|---|---|---|
| 没有这个字段 | 当前层不作决定 | 是 | 由上层结果决定 |
| 具体值 | 当前层自己设置 | 否 | 是 |
| `null` | 由模型决定 | 否 | 否 |

例如父节点保存：

```json
{
	"temperature": 0.7
}
```

子节点的三种状态分别为：

```text
继承上级    → 子节点不保存 temperature，请求发送 0.7
自己设置    → 子节点保存 temperature: 0.3，请求发送 0.3
由模型决定  → 子节点保存 temperature: null，请求不发送 temperature
```

### 旧数据

旧数据中的具体值一律视为“自己设置”。无法可靠判断它是用户填写的，还是旧界面自动保存的；擅自删除会改变已有端点和会话的行为。

## 端点参数界面

每个已注册参数由“决定方式”和“具体值”两部分组成。决定方式使用单选按钮；只有选择“自己设置”时才显示具体值控件。

### 顶层端点

顶层端点没有上级，只显示：

- **自己设置**
- **由模型决定**

字段不存在或值为 `null` 时都显示“由模型决定”，但保存时必须区分用户是否操作过这一项：

- 用户没有操作：保留原始状态。字段原本不存在就继续不存在，原本是 `null` 就继续保存 `null`。
- 用户明确点击“由模型决定”：保存 `null`。
- 用户选择“自己设置”：保存具体值。

字段不存在和 `null` 在顶层端点当前都不会发送，但端点以后若被移到某个父节点下，前者会开始继承，后者仍会阻止继承，因此不能在用户未操作时擅自互换。

### 子端点

子端点显示：

- **继承上级**
- **自己设置**
- **由模型决定**

打开窗口时按子节点自己的 `params` 判断状态，不能只读取已经合并父节点后的最终参数：

- 子节点没有该字段：显示“继承上级”。
- 子节点保存具体值：显示“自己设置”。
- 子节点保存 `null`：显示“由模型决定”。

若上级最终设置了该参数，“继承上级”旁显示实际值，例如“当前为 0.7”；若上级也没有设置，则显示“上级未设置，将由模型决定”。

### 具体值控件

- 只有选择“自己设置”才显示滑块、数字框、文本框或下拉框。
- 如果当前层已有具体值，显示该值。
- 如果当前层从未保存具体值，用户第一次选择“自己设置”时，用注册表的 `default` 作为建议起点。
- 建议起点只有在用户保存“自己设置”后才成为正式参数。
- 用户在同一次打开窗口期间切走再切回“自己设置”时，保留刚才输入的值。

## 会话参数界面

会话参数窗口使用与端点参数相同的控件，但决定方式名称反映会话层含义：

- **沿用端点设置**
- **自己设置**
- **由模型决定**

打开窗口时只用当前会话或工作区在该端点上的参数对象判断本层状态，端点最终参数只用于显示“沿用端点设置”将得到什么：

- 会话/工作区覆盖中没有该字段：显示“沿用端点设置”。
- 覆盖中保存具体值：显示“自己设置”。
- 覆盖中保存 `null`：显示“由模型决定”。

“由模型决定”会阻止端点和父节点已经设置的值进入这个会话。

## 保存规则

### 保存端点

逐个参数读取决定方式：

- 继承上级：不在当前节点的 `params` 中保存该字段。
- 自己设置：保存输入控件中的具体值。
- 由模型决定：保存 `null`。

每项参数在窗口打开时记录当前层的原始状态。只有用户操作过该参数的决定方式或具体值，保存时才按当前选择改写该字段；没有操作过则原样保留。用户只修改端点名称、地址或密钥时，参数决定方式和参数值保持原状。软件不得因为控件曾经显示建议值或默认选中的决定方式而新增参数。

### 保存会话参数

- 沿用端点设置：不在当前会话/工作区覆盖对象中保存该字段。
- 自己设置：保存具体值。
- 由模型决定：保存 `null`。

会话参数也记录打开窗口时的原始状态。用户没有操作某项参数时原样保留，不能因为默认选中了“沿用端点设置”而删除旧值。如果保存后覆盖对象不再包含任何字段，删除该端点的空覆盖对象，避免持久化无意义空对象。

### 自定义参数

自定义参数不增加决定方式。只有用户新增并填写键名后才保存；空键名不保存。

## 参数继承和请求生成

端点树解析参数时逐层处理：

1. 当前节点有具体值：使用该值，不再读取祖先同名参数。
2. 当前节点值为 `null`：保留 `null`，不再读取祖先同名参数。
3. 当前节点没有该字段：继续向祖先查找。

会话或工作区参数覆盖端点最终参数时遵守相同规则：

1. 覆盖对象有具体值：使用覆盖值。
2. 覆盖对象值为 `null`：最终结果为 `null`，阻止端点值。
3. 覆盖对象没有该字段：使用端点最终值。

请求生成器只发送具体值。值为 `null`、空字符串或字段不存在时均不发送。

OpenAI 新格式的 `reasoning_effort` 会转换成：

```json
{
	"reasoning": {
		"effort": "low"
	}
}
```

只有值为具体选项时才创建 `reasoning`。值为 `null` 或空字符串时，请求中连空的 `reasoning` 对象也不能出现。

## 错误处理

- 数字输入不合法时，不关闭窗口，不保存，并在对应参数旁说明合法范围。
- 用户选择“自己设置”但没有填写允许为空以外的值时，不保存，并提示填写。
- “继承上级”“沿用端点设置”和“由模型决定”不校验隐藏的具体值控件，因为隐藏值不会保存。
- 已有未知参数继续按现有自定义参数规则处理，不因注册表中找不到定义而自动删除。

## 受影响的代码边界

- `src/modules/params-registry.js`：继续提供参数定义和建议起点；`default` 不再表示自动发送值。
- `src/modules/attachments.js`：端点参数的三态显示、收集和保存。
- `src/modules/selected-endpoints.js`：会话参数的三态显示、收集和保存。
- `src/modules/store.js`：确认并保持“字段缺失时继承、`null` 时阻止继承”的参数解析规则。
- `src/modules/shared.js`：会话/工作区覆盖时保留 `null`，发送请求时跳过 `null`；修正 OpenAI 新格式思考强度绕过空值检查的问题。
- `src/layout.html`：如参数决定方式需要复用模板，在源码模板中定义，不由 JavaScript 拼接结构。
- `tests/endpoint-tree.test.js`：覆盖端点继承、弹窗保存和请求参数。
- `tests/storage.test.js`：仅在参数持久化结构需要补充覆盖时修改。

## 验证标准

1. 新建任意接口格式的端点，不设置参数，只修改名称并保存：端点中不出现参数建议值。
2. 父节点设置温度 0.7，子节点选择“继承上级”：请求发送 0.7。
3. 同一子节点选择“自己设置”0.3：请求发送 0.3。
4. 同一子节点选择“由模型决定”：请求不发送温度。
5. 端点设置温度 0.7，会话选择“沿用端点设置”：请求发送 0.7。
6. 同一会话选择“由模型决定”：请求不发送温度。
7. 已有端点保存过温度、最大回复长度等具体值：打开后仍显示“自己设置”，请求行为不变。
8. OpenAI 新格式没有设置思考强度：请求中不存在 `reasoning`。
9. OpenAI 新格式明确设置思考强度：请求中包含用户选择的值。
10. 顶层端点明确选择“由模型决定”后，保存值为 `null`，请求不发送该参数。
11. 顶层端点原本没有某参数时，用户只修改名称、地址或密钥并保存，该参数仍然不存在，不能自动变成 `null` 或建议值。
12. 用户只修改端点名称、地址或密钥时，已有参数状态和值保持不变。
13. 自定义参数仍只在用户填写后保存和发送。
14. 构建后，源码版、单页版和扩展版行为一致。
15. 页面加载和参数编辑过程中没有 `console.error` 或未捕获异常。
